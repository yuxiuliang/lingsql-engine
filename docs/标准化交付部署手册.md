# LingSQL 标准化交付部署手册（Docker）

> 版本：v1.0  
> 更新日期：2026-08-15
> 适用对象：实施工程师、SRE、售前技术

---

## 1. 目标

本手册用于快速搭建可演示、可验收、可试点的 LingSQL 标准环境，降低首单交付成本。

---

## 2. 先决条件

- Docker 24+  
- Docker Compose v2  
- 可访问容器镜像仓库（默认 Docker Hub）

---

## 3. 一键拉起（推荐）

1. 准备环境变量文件：

```bash
cp .env.example .env
```

2. 修改 `.env` 中关键参数（必须修改）：

- `MYSQL_ROOT_PASSWORD`
- `MYSQL_APP_USERNAME`
- `MYSQL_APP_PASSWORD`
- `REDIS_PASSWORD`
- `LINGSQL_JWT_SECRET`
- `LINGSQL_DATA_ENCRYPTION_KEY`
- `LINGSQL_ADMIN_PASSWORD`
- `LINGSQL_DEMO_DATABASE`
- `LINGSQL_DEMO_USERNAME`
- `LINGSQL_DEMO_PASSWORD`

3. 执行一键拉起：

```bash
./scripts/ops/bootstrap_local_stack.sh
```

脚本会自动完成以下动作：

- 启动 MySQL 与 Redis 容器
- 由初始化脚本创建应用账号，先撤销历史权限，再仅授予 `SELECT/INSERT/UPDATE/DELETE`；演示账号仅授予 `SELECT`
- 查询 `information_schema.SCHEMA_PRIVILEGES` 失败关闭校验，权限超出或缺失都会终止启动
- 运行短生命周期 Flyway 迁移任务；DDL 使用 root，应用账号不获得 DDL 权限
- 对空库执行冻结合并基线；对未纳管现有库先做完整结构指纹校验再显式 baseline
- 导入 `sql/seed_commercial_baseline.sql` 商业化基线套餐
- 初始化虚构的销售库存演示库
- 启动应用并等待 readiness 健康检查通过

---

## 4. 手动分步部署

若需要分步排障，可按以下命令执行：

手工直接执行 Compose 不会创建应用账号；必须至少运行一次初始化脚本。推荐用 `SKIP_APP_START=true` 完成数据库结构、账号权限和演示库初始化，再启动应用：

```bash
SKIP_APP_START=true bash scripts/ops/bootstrap_local_stack.sh
docker compose --env-file .env up -d app
```

---

## 5. 验收检查

应用启动后执行：

```bash
curl -fsS http://127.0.0.1:${APP_PORT:-8000}/actuator/health/readiness
bash scripts/ops/schema_drift_guard.sh
bash scripts/ops/flyway_migrate.sh
bash scripts/ops/security_compliance_guard.sh
bash scripts/ops/audit_delivery_guard.sh
docker compose --env-file .env exec -T mysql \
  mysql -uroot -p"${MYSQL_ROOT_PASSWORD}" -e "SHOW GRANTS FOR '${MYSQL_APP_USERNAME}'@'%';"
```

配置试点账号、只读数据源和模型后，必须执行真实业务验收；只通过健康检查不能交付：

```bash
BASE_URL=http://127.0.0.1:${APP_PORT:-8000} \
PILOT_TENANT_ID=<tenant> PILOT_USERNAME=<user> PILOT_PASSWORD=<password> \
PILOT_CONTROL_TOKEN=<system-admin-token> \
bash scripts/ops/pilot_acceptance.sh
```

如需完整商用门禁：

```bash
BASE_URL=http://127.0.0.1:${APP_PORT:-8000} \
BILLING_READINESS_URL=http://127.0.0.1:${APP_PORT:-8000}/api/v1/admin/billing/readiness/snapshot \
BILLING_AUTH_HEADER="Authorization: Bearer <token>" \
PILOT_TENANT_ID=<tenant> PILOT_USERNAME=<user> PILOT_PASSWORD=<password> \
PILOT_CONTROL_TOKEN=<system-admin-token> \
bash scripts/ops/commercial_acceptance_gate.sh
```

GitHub 的严格发布工作流必须配置独立系统管理验收账号的 `RELEASE_GATE_CONTROL_TOKEN`，并映射为运行时 `PILOT_CONTROL_TOKEN`。该 Token 仅保存于受保护的发布环境 Secrets；不得与普通试点账号共用，也不得把普通试点账号提升为系统管理员。

## 7. 生产建议

- 使用外部托管 MySQL/Redis，并开启备份与高可用。
- Compose 默认仅把 MySQL、Redis 和应用端口绑定到 `127.0.0.1`；只有经防火墙、TLS 网关和访问控制评审后才可修改 `*_BIND_ADDRESS`。
- 应用容器使用非 root UID、只读根文件系统、`no-new-privileges` 并移除 Linux capabilities；客户环境不得删除这些约束来规避权限问题。
- `LINGSQL_RETENTION_DRY_RUN` 先保持 `true`，观察 7 天后再关闭。
- 通过网关/Nginx 统一接入 HTTPS，限制管理端来源 IP。
- 将 `.env` 纳入密钥管理系统，不在仓库中明文保存。
- 生产发布必须先备份，再由部署平台配置的 `LINGSQL_MIGRATION_HOOK` 执行 Flyway；应用制品回滚不会自动回滚数据库。
- 所有新迁移必须向前兼容上一稳定应用版本。MySQL 多条 DDL 不具备整体事务回滚能力，失败后禁止未经核验直接 `repair`。
