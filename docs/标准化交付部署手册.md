# LingSQL 标准化交付部署手册（Docker）

> 版本：v1.0  
> 更新日期：2026-08-15
> 适用对象：实施工程师、SRE、售前技术

---

## 1. 目标

本手册用于快速搭建可演示、可验收、可试点的 LingSQL 标准环境，降低首单交付成本。

---

## 2. 先决条件

- Docker 24+  
- Docker Compose v2  
- 可访问容器镜像仓库（默认 Docker Hub）

---

## 3. 一键拉起（推荐）

1. 准备环境变量文件：

```bash
cp .env.example .env
```

2. 修改 `.env` 中关键参数（必须修改）：

- `MYSQL_ROOT_PASSWORD`
- `MYSQL_APP_USERNAME`
- `MYSQL_APP_PASSWORD`
- `REDIS_PASSWORD`
- `LINGSQL_JWT_SECRET`
- `LINGSQL_DATA_ENCRYPTION_KEY`
- `LINGSQL_ADMIN_PASSWORD`
- `LINGSQL_DEMO_DATABASE`
- `LINGSQL_DEMO_USERNAME`
- `LINGSQL_DEMO_PASSWORD`

3. 执行一键拉起：

```bash
./scripts/ops/bootstrap_local_stack.sh
```

脚本会自动完成以下动作：

- 启动 MySQL 与 Redis 容器
- 由初始化脚本创建应用账号，先撤销历史权限，再仅授予 `SELECT/INSERT/UPDATE/DELETE`；演示账号仅授予 `SELECT`
- 查询 `information_schema.SCHEMA_PRIVILEGES` 失败关闭校验，权限超出或缺失都会终止启动
- 运行短生命周期 Flyway 迁移任务；DDL 使用 root，应用账号不获得 DDL 权限
- 对空库执行冻结合并基线；对未纳管现有库先做完整结构指纹校验再显式 baseline
- 导入 `sql/seed_commercial_baseline.sql` 商业化基线套餐
- 初始化虚构的销售库存演示库
- 启动应用并等待 readiness 健康检查通过

---

## 4. 手动分步部署

若需要分步排障，可按以下命令执行：

手工直接执行 Compose 不会创建应用账号；必须至少运行一次初始化脚本。推荐用 `SKIP_APP_START=true` 完成数据库结构、账号权限和演示库初始化，再启动应用：

```bash
SKIP_APP_START=true bash scripts/ops/bootstrap_local_stack.sh
docker compose --env-file .env up -d app
```

## 5. 验收检查

### 5.1 首次开户顺序

首次开户必须按以下顺序完成，任何一步未通过都不得把租户标记为“可试用”：

1. 在“租户管理”创建租户，并同时填写首个租户管理员账号。系统会在同一事务内创建租户、角色、账号和角色绑定，不再允许创建无登录账号的空租户。
2. 保存只读业务数据源。更新数据源后系统会把 Schema 状态重置为“待同步”，并在事务提交后关闭旧连接池、清理旧 Schema 缓存；不得沿用修改前的“同步成功”状态。
3. 用“测试连接”执行 `SELECT 1`，随后同步 Schema，确认表数量与客户批准的白名单一致。
4. 新增或修改模型配置后，系统会强制停用并重置为“待验证”。点击“验证”实际调用 `/v1/chat/completions`，验证通过后再由管理员显式启用；健康页出现“未验证”或“验证失败”时不得进入真实问数验收。
5. 使用新建的租户管理员账号登录，再执行三问和 40 题验收。系统管理员账号不能替代租户账号证明权限边界。

租户管理员初始密码属于一次性交付凭据，应通过约定的安全通道发送并要求客户首次登录后重置；不得写入报告、工单正文、聊天记录或仓库文件。

对于仓库自带的虚构销售库存演示，可在 `.env` 中填写演示管理员和模型参数后执行以下单一入口。它会完成基础设施、演示租户与管理员、白名单数据源、连接验证、Schema 同步、模型真实 Probe/启用和三问验收；已有资源会按稳定 ID 复核，任何不一致或未验证步骤都会失败关闭：

```bash
bash scripts/ops/bootstrap_demo_pilot.sh
```

若 `.env` 未填写 `LINGSQL_DEMO_MODEL_*`，脚本只复用已经处于 `HEALTHY + active` 的模型；没有可用模型时不会生成假 PASS。重复执行时可设置 `SKIP_INFRA_BOOTSTRAP=true`，但仍会重新验证账号、数据源、Schema、模型和三问闭环。

应用启动后执行：

```bash
curl -fsS http://127.0.0.1:${APP_PORT:-8000}/actuator/health/readiness
bash scripts/ops/schema_drift_guard.sh
bash scripts/ops/flyway_migrate.sh
bash scripts/ops/security_compliance_guard.sh
bash scripts/ops/audit_delivery_guard.sh
docker compose --env-file .env exec -T mysql \
  mysql -uroot -p"${MYSQL_ROOT_PASSWORD}" -e "SHOW GRANTS FOR '${MYSQL_APP_USERNAME}'@'%';"
```

配置试点账号、只读数据源和模型后，必须执行真实业务验收；只通过健康检查不能交付：

```bash
BASE_URL=http://127.0.0.1:${APP_PORT:-8000} \
PILOT_TENANT_ID=<tenant> PILOT_USERNAME=<user> PILOT_PASSWORD=<password> \
PILOT_CONTROL_TOKEN=<dedicated-system-admin-acceptance-token> \
bash scripts/ops/pilot_acceptance.sh
```

手工/UAT 环境不便预先提取短期 Token 时，可用独立控制身份让脚本自行登录；不得回退使用普通试点账号：

```bash
PILOT_CONTROL_TENANT_ID=<system-tenant> \
PILOT_CONTROL_USERNAME=<acceptance-admin> \
PILOT_CONTROL_PASSWORD=<secret> \
bash scripts/ops/pilot_acceptance.sh
```

三条真实问数只证明环境闭环，不能替代客户的 40 题正式验收。双方冻结符合 `docs/schemas/golden-question-suite.schema.json` 的 JSON 后，必须在同一 self-hosted UAT 串行执行 FIRST；有错误题时以不变的 Suite SHA-256 引用首次证据执行 RETEST：

```bash
GQ_SUITE_FILE=./customer-golden-questions.json \
GQ_PHASE=FIRST \
GQ_OUTPUT_DIR=./reports/customer-gq-first \
BASE_URL=http://127.0.0.1:${APP_PORT:-8000} \
PILOT_TENANT_ID=<tenant> PILOT_USERNAME=<user> PILOT_PASSWORD=<password> \
PILOT_CONTROL_TOKEN=<dedicated-system-admin-acceptance-token> \
bash scripts/ops/golden_question_acceptance.sh
```

自动门禁通过后仍须双方核对冻结 JSON、受控业务材料和脱敏报告并签字；未签字不得标记为客户验收通过。完整的 FIRST/RETEST、准确率、P95、效率改善、安全拦截和逐请求资金守恒规则见 `docs/黄金问题与验收复测记录模板.md`。

如需完整商用门禁：

```bash
BASE_URL=http://127.0.0.1:${APP_PORT:-8000} \
BILLING_READINESS_URL=http://127.0.0.1:${APP_PORT:-8000}/api/v1/admin/billing/readiness/snapshot \
BILLING_AUTH_HEADER="Authorization: Bearer <token>" \
PILOT_TENANT_ID=<tenant> PILOT_USERNAME=<user> PILOT_PASSWORD=<password> \
PILOT_CONTROL_TOKEN=<dedicated-system-admin-acceptance-token> \
BACKUP_RESTORE_MYSQL_HOST=<uat-mysql-host> \
BACKUP_RESTORE_SOURCE_DB=<control-db> \
BACKUP_RESTORE_TARGET_DB=lingsql_restore_verify_<unique-run-id> \
BACKUP_RESTORE_BACKUP_USER=<backup-user> \
BACKUP_RESTORE_BACKUP_PASSWORD=<backup-password> \
BACKUP_RESTORE_RESTORE_USER=<restore-user> \
BACKUP_RESTORE_RESTORE_PASSWORD=<restore-password> \
BACKUP_RESTORE_BACKUP_DIR=/absolute/protected/backup/path \
BACKUP_RESTORE_WORK_ROOT=/absolute/temporary/path \
BACKUP_RESTORE_SAMPLE_QUERY='<single read-only SELECT>' \
bash scripts/ops/commercial_acceptance_gate.sh
```

GitHub 的严格发布工作流必须配置独立系统租户验收账号的 `RELEASE_GATE_CONTROL_TOKEN`，并映射为运行时 `PILOT_CONTROL_TOKEN`。该账号必须具备 `ADMIN:SQLLOG:READ`、`ADMIN:BILLING:READ` 和系统管理员身份；Token 仅保存于受保护的 UAT Environment Secrets，不得与普通试点账号或 `RELEASE_GATE_BILLING_TOKEN` 共用，也不得把普通试点账号提升为系统管理员。`PILOT_CONTROL_TENANT_ID/USERNAME/PASSWORD` 只用于受控人工环境的即时登录，不进入 GitHub 工作流或仓库。

### 5.2 备份恢复抽查

商用总门禁会调用 `scripts/ops/backup_restore_acceptance.sh`。该脚本复用 `mysql_backup.sh` 与 `mysql_restore.sh`，执行以下不可跳过检查：

1. 使用只读备份账号对 UAT 控制库创建本次真实备份并验证 SHA-256。
2. 备份前后分别计算结构与客户配置的只读样例数据指纹；源库在备份窗口发生变化时失败，避免用不稳定快照出具证明。
3. 只允许恢复到运行前不存在的 `lingsql_restore_verify_` 前缀数据库，禁止指向源库或覆盖已有数据库。
4. 恢复后重新计算结构和样例指纹并逐项比对。
5. 退出时只清理固定验证前缀数据库和受控绝对临时目录；真实备份保留在受保护绝对路径，报告只记录不可逆摘要。

备份账号应只有读取、`LOCK TABLES`、视图/触发器/事件导出所需权限；恢复账号只能在隔离 UAT 实例创建和删除验证前缀数据库，不得连接生产 MySQL。样例查询必须是一条无分号 `SELECT`，返回稳定的计数/聚合结果，且不得输出客户明细。self-hosted Runner 必须安装 `mysql`、`mysqldump`、`gzip` 与 `sha256sum`。

严格工作流的 Environment Variables：

- `RELEASE_GATE_MYSQL_HOST`、`RELEASE_GATE_MYSQL_PORT`
- `RELEASE_GATE_BACKUP_SOURCE_DB`、`RELEASE_GATE_BACKUP_DIR`（self-hosted Runner 上的受保护绝对路径）
- `RELEASE_GATE_BACKUP_USER`、`RELEASE_GATE_RESTORE_USER`

严格工作流的 Environment Secrets：

- `RELEASE_GATE_BACKUP_PASSWORD`、`RELEASE_GATE_RESTORE_PASSWORD`
- `RELEASE_GATE_BACKUP_SAMPLE_QUERY`

## 7. 生产建议

- 使用外部托管 MySQL/Redis，并开启备份与高可用。
- Compose 默认仅把 MySQL、Redis 和应用端口绑定到 `127.0.0.1`；只有经防火墙、TLS 网关和访问控制评审后才可修改 `*_BIND_ADDRESS`。
- 应用容器使用非 root UID、只读根文件系统、`no-new-privileges` 并移除 Linux capabilities；客户环境不得删除这些约束来规避权限问题。
- `LINGSQL_RETENTION_DRY_RUN` 先保持 `true`，观察 7 天后再关闭。
- 通过网关/Nginx 统一接入 HTTPS，限制管理端来源 IP。
- 将 `.env` 纳入密钥管理系统，不在仓库中明文保存。
- 生产发布必须先备份，再由部署平台配置的 `LINGSQL_MIGRATION_HOOK` 执行 Flyway；应用制品回滚不会自动回滚数据库。
- 所有新迁移必须向前兼容上一稳定应用版本。MySQL 多条 DDL 不具备整体事务回滚能力，失败后禁止未经核验直接 `repair`。
